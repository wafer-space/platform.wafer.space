# Crowd Supply order number on Project — Design

**Date:** 2026-06-09
**Branch:** `feature/crowd-supply-order-id` (based on PR #260, `fix/zip-mime-detection`)
**Status:** Approved (pending spec review)

## Problem

A project on the platform may correspond to a hardware purchase made through
[Crowd Supply](https://www.crowdsupply.com/). Today there is no way to record
which Crowd Supply order a project relates to, so staff and owners cannot link a
manufactured design back to its order.

We want project owners to be able to associate a Crowd Supply **order number**
with their project.

## Requirements (from brainstorming)

| Decision | Choice |
| --- | --- |
| Who can set/edit it | **Project owner** (always-editable user field; staff can also edit) |
| Cardinality | **One order per project, optional**; numbers may repeat across projects |
| Format | Numeric order ID, e.g. `327373` |
| Where shown | Project edit form, project detail page, Django admin |
| Order URL | `https://www.crowdsupply.com/account/order/<order_id>` |

Explicitly **out of scope** (YAGNI):

- No uniqueness constraint across projects.
- No verification/lookup against Crowd Supply's API.
- No "verified" flag or staff-approval workflow.
- No backfill/data migration (field is optional, defaults to empty).

## Approach

Store the order ID as a **`CharField`**, not an integer. Order IDs are opaque
identifiers, not quantities: we never do arithmetic on them, leading characters
could matter, and a string column survives any future format change Crowd Supply
makes. This mirrors how the existing `project_id` identifier is stored.

This follows the established pattern in the codebase for optional,
owner-editable project metadata (`repository_url`, `other_license_spdx_id`):
a model field listed in `USER_FIELDS`, surfaced via `ProjectForm.Meta`,
searchable in admin, and conditionally rendered in the detail template.

**Rejected alternative:** `PositiveIntegerField`. Rejected because order IDs are
identifiers, not numbers to compute with, and an integer column would lock us
out of any future non-numeric format.

## Design

### 1. Model (`wafer_space/projects/models.py`)

New module-level validator beside `validate_project_id`:

```python
def validate_crowd_supply_order_id(value: str) -> None:
    """Validate a Crowd Supply order id is all digits (e.g. "327373")."""
    if not value.isdigit():
        msg = "Crowd Supply order number must contain only digits (e.g. 327373)."
        raise ValidationError(msg)
```

New field on `Project`:

```python
crowd_supply_order_id = models.CharField(
    max_length=20,
    blank=True,
    default="",
    validators=[validate_crowd_supply_order_id],
    help_text="Crowd Supply order number, e.g. 327373 (optional).",
)
```

- Added to the `USER_FIELDS` frozenset → always editable by the owner, never
  locked by `_validate_core_fields_immutable()`, and automatically change-tracked
  by `HistoricalRecords`.
- Django skips validators on blank values (empty string is in `Field.empty_values`),
  so the "optional" behaviour is preserved without special-casing.

New computed property (mirroring `full_id`):

```python
@property
def crowd_supply_order_url(self) -> str:
    """Crowd Supply order page URL, or '' when no order id is set."""
    if not self.crowd_supply_order_id:
        return ""
    return f"https://www.crowdsupply.com/account/order/{self.crowd_supply_order_id}"
```

### 2. Migration

`wafer_space/projects/migrations/0056_add_crowd_supply_order_id.py`, generated by
`makemigrations`. A single migration covers both `Project` and `HistoricalProject`
(simple-history adds the column to the history table in the same migration).

### 3. Form (`wafer_space/projects/forms.py`)

- Add `"crowd_supply_order_id"` to `ProjectForm.Meta.fields` in the User-fields
  section.
- Widget: `forms.TextInput(attrs={"class": "form-control", "placeholder": "327373",
  "inputmode": "numeric"})`.
- `help_texts` entry.
- `clean_crowd_supply_order_id()`: strip surrounding whitespace and a single
  leading `#`, so a pasted `#327373` is accepted before the model validator runs.
  Returns `""` unchanged when empty.

### 4. Admin (`wafer_space/projects/admin.py`)

- Add `"crowd_supply_order_id"` to `ProjectAdmin.list_display`.
- Add `"crowd_supply_order_id"` to `ProjectAdmin.search_fields`.
- `ProjectAdmin` defines no custom `fields`/`fieldsets`, so the field becomes
  editable in the admin form automatically.

### 5. Detail page (`wafer_space/templates/projects/project_detail.html`)

In the "Project Details" card, alongside the existing Repository/License rows,
add a conditional row:

```html
{% if project.crowd_supply_order_id %}
  <p>
    <strong>Crowd Supply order:</strong>
    <a href="{{ project.crowd_supply_order_url }}" target="_blank" rel="noopener">
      {{ project.crowd_supply_order_id }}
    </a>
  </p>
{% endif %}
```

The raw number is the link text so the identifier stays visible/copyable even for
viewers who can't open the account-scoped order URL.

## Testing (TDD)

Tests written before implementation, mirroring the source layout:

- **Validator** (`tests/test_models.py`): accepts `"327373"`; rejects `"abc"`,
  `"3273 73"`, `"#327373"`, `"32.73"`; blank value passes model `full_clean()`.
- **`crowd_supply_order_url` property**: returns the expected URL for a set id;
  returns `""` when unset.
- **Form** (`tests/test_forms.py`): `clean_crowd_supply_order_id` normalises
  `"  #327373 "` → `"327373"`; rejects non-numeric; empty stays empty and valid.
- **Model round-trip**: save + reload preserves the value; history row records it.

All of `make lint-fix && make lint && make type-check && make test` must pass
before commit, per project policy.
